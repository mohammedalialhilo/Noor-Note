# Public publishing

For secret, single-note links with password and expiration controls, see [private share links](private-share-links.md). A private link does not add a page to the public site.

Publishing is opt-in per note. A signed-in Owner or Admin with plaintext cloud sync enabled creates a site in **Settings → Public publishing**, checks the approval box for a specific note, and chooses **Publish note**. **Update public page** publishes a new snapshot; normal local edits do not change the public page. **Unpublish** removes the snapshot. Publishing is unavailable for local-only and encrypted vaults.

Deploy the `202609300002_noor_publishing.sql` migration after the sharing migration. Configure `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in Netlify. The same publishable key is used by the browser and Netlify Function; no service-role key is required. `netlify.toml` routes `/p/*` to `apps/web/netlify/functions/publish.tsx`. Run `pnpm --filter @noor-note/web build` before deployment; the build generates the local Mermaid bundle and KaTeX assets. For local end-to-end routing, use Netlify Dev; `next dev` serves only the application shell.

The publication tables store copied note bodies and selected image IDs. YAML frontmatter and Noor Note internal ID comments are removed from the public copy. They never query private sync records while serving a page. RLS lets anonymous visitors read only public site and page rows. Published images are stored in a private bucket; anonymous Storage reads require an asset ID in the current published page snapshot or site branding fields. The Netlify Function checks the current snapshot on every request and sends `Cache-Control: no-store`. Unpublishing or updating removes public access to old image IDs. Previously downloaded or externally cached copies cannot be recalled.

The public renderer resolves wiki links, Markdown note links, backlinks, navigation, and graph edges against **published pages only**. Missing and private links appear as plain text. The renderer skips raw Markdown HTML and uses React's escaping. Mermaid runs with strict security in a local bundle. Public pages have a table of contents, responsive light/dark themes, KaTeX, code highlighting, metadata, OpenGraph, canonical URLs, and a configurable `noindex`/`index` setting. The optional graph shows at most 120 published nodes for rendering performance.

Site settings include slug, title, description, theme, logo, favicon, navigation slugs, homepage, robots mode, and graph toggle. Only navigation slugs that match published pages appear. Public paths are `/p/{site-slug}`, `/p/{site-slug}/{page-slug}`, and optionally `/p/{site-slug}/graph`.

Limits: one public site per synced vault, 1 MiB Markdown per page, 30 local images per page, 8 MiB per image, raster PNG/JPEG/WebP/GIF/AVIF only. External HTTPS images authored in a selected note can appear on the page; review these before publishing. Changing a slug changes its URL without redirects. There are no custom domains, publication scheduling, or public comments yet. Live Netlify and Supabase deployment still needs project-level verification.
