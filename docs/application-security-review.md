# Application security review

Reviewed 2026-10-02 against the local web app, browser extension, Netlify Functions, plugin bridge, importers, and Supabase migration tests. The review treated Markdown, YAML, file and attachment names and bytes, URLs, Canvas JSON, comments, plugins, search queries, AI responses, ZIPs, and share links as attacker-controlled. It combined source-to-sink inspection with focused regression tests. It is not an independent penetration test or a live deployment audit.

## Findings fixed

| Boundary | Finding | Change and regression |
| --- | --- | --- |
| Same-origin file delivery | Arbitrary attachment Blobs could be opened as documents from the explorer; Canvas PDF cards embedded a Blob without an iframe sandbox. A mislabeled HTML file could acquire an active document context. | Generic files now download. Inline raster/PDF preview requires a byte signature and forces the browser MIME; Canvas PDFs use `sandbox=""` and no referrer. Tests cover HTML/SVG bytes under false MIME labels and the iframe. |
| Public and local image preview | Image previews and public assets trusted recorded MIME alone. | Local previews and the public asset Function verify supported raster signatures. Publishing image uploads also verify bytes. SVG is excluded from inline image preview. Tests cover accepted and rejected signatures. |
| YAML metadata | An untrusted `__proto__`/`constructor`/`prototype` field could enter ordinary metadata maps. | Inspected property maps use null prototypes and skip those field names; their original YAML remains portable. Tests cover prototype-shaped fields and mutation attempts. |
| Plugin network permission | A declared origin could target local or private-looking hosts, or use credentials or a custom port. | Manifest validation and runtime request handling require an exact public HTTPS origin, reject local/IP hosts, credentials, ports, and redirects; requests omit credentials. Tests cover denied origins and grants. |
| ZIP import | Declared `uncompressedSize` was checked, but extracted bytes were not counted while decompressing. | Both Import Center and native vault ZIP paths now count actual output bytes through a bounded stream; native attachment size must match the manifest. Tests use a forged size field over a real ZIP entry. |
| Extension HTML capture | Conversion assigned captured HTML to a detached element's `innerHTML`. | Conversion parses an inert HTML document with `DOMParser` before Markdown conversion. A malicious-HTML capture test verifies inert output. |
| Malformed wiki URL | A malformed encoded link could throw during reading preview. | Decoding failure now leaves the link inert instead of crashing the view. Rendering tests cover the case. |

## Boundary audit

| Attack area | Reviewed behavior and remaining scope |
| --- | --- |
| Stored/DOM XSS, Markdown injection, unsafe HTML | React views render text through React. Reading, publishing, and private sharing skip raw note HTML and reject active Markdown URL schemes. Focused tests feed scripts, handlers, and `javascript:`/`data:` links into private and public renderers. The extension conversion is inert. Browser-level tests are still needed for all Markdown extensions and third-party parser updates. |
| URL schemes, open redirects, unsafe iframe embeds | Canvas and bookmark external URLs are HTTP(S) only; external windows use `noopener,noreferrer`. Auth callback redirects are same origin; private-share redirects use a path. The only local attachment iframe is a signature-checked sandboxed PDF. User-supplied remote images in public Markdown may cause visitor-side requests and tracking; they are not fetched by a Noor server. |
| Path traversal and ZIP slip | Vault paths reject traversal; ZIP entry names are validated before use and are never extracted to OS paths. Archive entry counts, advertised totals, and actual extraction per entry are bounded. A crafted ZIP parser exploit or hostile browser memory pressure remains possible. |
| Prototype pollution | YAML-derived application maps reject dangerous top-level keys. Domain JSON and Canvas data pass Zod schemas before use; further fuzzing of nested imported objects is advisable. |
| CSRF, IDOR, SQL injection | Mutating cloud operations use bearer credentials and server-side Supabase RLS/RPC authorization. The private-share cookie route checks origin and uses SameSite cookies. Queries use fixed SQL migrations or the Supabase query builder. The embedded PostgreSQL suite covers cross-user and role access; a live Supabase project is still needed for Auth, Storage, and Realtime behavior. |
| Uploads and MIME confusion | Private attachments are stored as data and generic attachments download. Inline preview and public asset delivery require known raster/PDF signatures. This header check is not a complete file format validator; PDF.js, browser decoders, and OCR still process potentially malformed media. |
| Credentials and CSP | Browser config uses a publishable Supabase key; protected server credentials are not bundled. Public/private Functions and static export use CSP and no-store where appropriate. The app CSP permits `data:` scripts for sandboxed plugins, styles for the editor, and WebAssembly for local models; CSP must not be treated as the sole XSS control. Confirm generated headers on the deployed site. |
| Plugins | Plugin code runs in an opaque-origin sandbox and crosses a permissioned message bridge. Network capability is restricted as above. A user-approved plugin can still misuse data explicitly granted to it; public DNS names can also later resolve differently, so browser-level isolation and DNS rebinding review remain. |
| SSRF | The reviewed Netlify Functions contact only configured Supabase endpoints, not a user-provided URL. Plugin network requests run in the browser and are restricted to a granted origin. Re-audit when adding server fetch, URL previews, or hosted AI providers. |
| Search and AI prompt injection | Search runs in a local worker; regex is bounded but not exhaustively proven safe against all expensive patterns. AI is opt-in with explicit content review, and responses enter a preview before edits. Retrieved note text and AI output remain untrusted instructions; provider-side prompt injection cannot be ruled out by a client parser. |
| Share links | Tokens are random bearer secrets stored as hashes, with expiry/revocation checks in the access RPC. Password verifiers are bcrypt hashes. Private routes avoid caching and enforce origin on session-creating POSTs. A copied link remains usable until expiry or revocation. |

## Validation and deployment follow-up

Run `corepack pnpm lint`, `corepack pnpm typecheck`, `corepack pnpm test`, and `corepack pnpm build` after changes. The focused files are `apps/web/test/security-rendering.test.ts`, `safe-attachment-preview.test.ts`, `canvas-attachment-security.test.tsx`, and `zip-safety.test.ts`, plus core metadata, plugin SDK, and clipper capture tests. Before public deployment, test the generated Netlify headers and Supabase RLS/Storage/Realtime policies on an isolated live project, exercise plugin and PDF behavior in supported browsers, fuzz archive and Markdown parser boundaries, and obtain an independent review.
