# Private share links

Private links are separate from public publishing. An Owner or Admin of a plaintext synced vault chooses a single note in **Settings → Private share links**, approves sharing its body, and selects an expiration, optional password, and Markdown download setting. The recipient opens `/s/{token}`. Private shares are not indexed, added to public navigation, or included in the public graph. Linked notes and local attachments are not included. Updating the local note does not update an existing link snapshot.

Apply `202609300003_noor_private_shares.sql` after the sharing migration. It requires PostgreSQL `pgcrypto` in the `extensions` schema and enables it there if absent. Netlify serves `/s/*` with `apps/web/netlify/functions/private-share.tsx` and uses only the Supabase publishable key. No service-role credential is needed. Test with Netlify Dev; the static Next.js development server does not serve this route.

The database generates each link token from two independent random UUIDv4 values, giving 244 random bits. It stores only SHA-256 of the token. The token is returned once, at creation; Noor Note cannot display it again. Passwords are hashed with `pgcrypto` bcrypt at cost 12 with a fresh salt. Passwords must be 12 or more characters and no more than 72 UTF-8 bytes, the bcrypt input limit. Neither plaintext password nor password hash is exposed by the share metadata query. Five wrong guesses lock a link for 15 minutes.

Anonymous roles have no direct table access. The narrow `noor_open_private_share` database function checks the token, expiration, revocation, password, and optional session before returning the note body. A correct password creates a random 12-hour session token; only its SHA-256 hash is stored. The Netlify Function sets the token in an HttpOnly, SameSite cookie scoped to that share URL. Every view and download request checks the current database state, so revocation also invalidates live sessions. Responses use `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, a restrictive CSP, and no search indexing. The password is sent only in a POST body, never a URL query.

The download toggle controls Noor Note's `.md` download endpoint and button. **View-only content can still be copied, saved, or captured by a recipient's browser.** It is not digital rights management. Local images and other attachments are not included yet. A recipient who knows the complete secret link can open an unprotected share, so send the link through a trusted channel; for sensitive content, set a separate password and send it through a different channel. Links can also appear in browser history and hosting access logs. Revocation cannot erase a copy the recipient already saved.

Current limits: plaintext synced vaults only; one note per link; snapshots up to 1 MiB; optional expiry up to one year; 12-hour password sessions; no live Netlify/Supabase deployment verification. The next development step is private attachment delivery with the same per-request token and session checks.
