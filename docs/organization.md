# Knowledge organization

The **Organize knowledge** view is an optional review surface. A vault scan reads at most 150 active note bodies on demand and derives suggestions locally. It does not modify any note. The current scan includes related and similar vocabulary, exact or highly similar duplicates, unlinked title mentions, orphan notes, established tags mentioned in text, explicit due dates, plain text action lines, root notes matching folder names, folders with enough notes for an index, and simple opposing `is`/`is not` statements. These are leads for human review, not factual conclusions.

Each card shows its source and evidence. **Preview** displays the proposed Markdown before **Accept** is enabled. Move and index actions have separate path/content previews and are excluded from **Accept all safe items**. The safe batch contains only Markdown links, YAML tags and properties, and checkbox conversions; it previews each affected note and writes one revision per note in the repository's atomic, revision-checked transaction. If the vault changed after scanning, the transaction fails and the user must scan again. Reject removes a suggestion from the current review only. The most recent accepted change can be undone while the review is open; undo checks current revisions, and undoing a new index moves it to Trash.

The optional **Review AI request** action works on one selected note. The default AI policy is disabled. When enabled for the current-note scope, the gateway shows the local provider, instruction, and exact note text before inference. The local model receives at most 4,000 characters. A strict JSON parser accepts only grounded tag, property, and task suggestions whose evidence is an exact substring of the reviewed note. Malformed or unsupported outputs are rejected. A single quoted sentence cannot prove a contradiction, so model contradiction claims are discarded. No external provider is configured. Model suggestions use the same preview and save path as local suggestions.

Limitations: this phase scans only the first 150 notes per request, uses simple lexical similarity rather than embeddings for pair suggestions, and recognizes a narrow form of contradictions. Suggestions and rejection state are not persisted. Large-vault scans and model quality need browser performance evaluation. No note is deleted, merged, moved, or rewritten without a separate explicit acceptance.
