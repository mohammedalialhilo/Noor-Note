# Chat with your vault

Vault chat keeps fixed application rules, the user's question, and retrieved passages in separate model messages. Passage text is JSON-encoded as untrusted data, including text imported from web clips. See [AI trust boundaries](ai-trust-boundaries.md).

Vault chat is an optional, local retrieval-augmented assistant. Open **Vault chat** from the activity bar or navigation. Enable **Only when I explicitly invoke it** in AI settings and allow the relevant scope. Current note, selected notes, and Base results have their own permissions; folder requests use the folder-and-vault retrieval permission. The local chat model has a first-use download. Noor Note remains usable with AI disabled.

Choose **Current note**, up to 20 **Selected notes**, a **Folder** (including descendants), a saved **Base**, or the **Entire vault**. A Base uses its saved query and formulas to establish the eligible notes. The local lexical search worker may index all note bodies on first use; it never sends them to the AI provider. Retrieval then loads at most 12 candidate bodies into its passage ranker. At most four passages from at most four notes are supplied to the model. The rest of the vault is not passed to the provider. Current and selected-note scopes search only their named notes. Retrieval currently uses lexical terms; it does not yet use the separate semantic vector index. A question with no matching passage receives an insufficient-evidence response without invoking the model.

Each generation opens a review of the provider, destination, scope, application task, user question, and exact passage text. The user must approve that request separately. The supplied passage labels (`[S1]` through `[S4]`) are created from real note records with stable note IDs, heading or block IDs when available, source ranges, lines, and revisions. The model is instructed to answer only from those passages. Answers with unknown or missing source labels are replaced with **“The vault does not contain enough evidence to answer that question.”** Citations in accepted answers are clickable; Noor Note reopens the note and locates the passage by text or its heading/block fallback. Saved citations indicate when the note revision has changed. Citation validation prevents invented Noor Note source identities, but the small local model can still misinterpret real evidence. Review important answers against their sources.

Chat history starts **off**. Enabling **Save this conversation on this device** stores messages and source references in a separate `noor-note-chats` IndexedDB database. Saved chats can be opened, deleted individually, or deleted for the current vault. **Export chats** downloads JSON containing saved chats and the current unsaved conversation. Chats are not included in vault ZIPs; note Markdown remains the authoritative knowledge source. The chat database is browser-local and has no server sync or encryption.

The local model downloads weights on first use. Note passages and questions are sent to the same-origin worker only after review; no remote assistant provider is configured. A short follow-up containing a pronoun can use the previous user question to find passages. The scope review includes user-authored previous questions for conversational context, but does not carry prior assistant answers into a request made under a different scope. Retrieval, first-use model behavior, and citation navigation need full-device accessibility and browser testing.
