# Security and privacy

Voice recording requests microphone permission only after the user presses Record. Capture stays in the browser; tracks stop on Stop or when the recorder closes. Draft and playback Blob URLs are revoked when no longer used. The app does not transmit audio or retain an unsaved draft after the recorder closes. A future hosted transcription service will need a separate opt-in and data-flow review.

Recording renames preview affected Markdown and check note revisions before an IndexedDB transaction updates the attachment path and note links. The rewrite skips YAML and fenced or inline code; unusual links may need manual review.

The current app is local-first and has optional Supabase Auth accounts and opt-in cloud sync, but no application telemetry. Normal vault operations remain in origin-scoped browser storage regardless of account status. Browser storage is **not encrypted or a backup**; anyone with access to the browser profile may read it, and clearing site data may erase it.

The account client accepts only a public Supabase publishable key and HTTPS project origin (or a local development origin). It uses PKCE, SDK-managed session persistence and refresh, exact same-origin redirects, and local-scope sign-out by default. Passwords are passed directly to Supabase Auth and are not stored in Noor Note data. Supabase browser sessions live in browser storage; this static deployment has no HTTP-only server session. User information in the browser is for display only, never server authorization. The cloud migrations restrict vault rows and private Storage paths to the authenticated owner; these policies still require live-project RLS tests. Ordinary sync remains readable to the Supabase project. New vaults can opt into end-to-end encrypted sync before their first upload; this protects record contents and attachment bytes but leaves routing metadata and access patterns visible. See [encryption](encryption.md), [authentication](authentication.md), and [sync protocol](sync-protocol.md).

Assistant AI is disabled by default. A local browser model provides note actions; no external chat or embedding provider is connected. The AI policy is stored locally; malformed preferences fall back to disabled. Scope permissions alone do not authorize a request. The gateway requires a per-request review of the provider, destination, prompt, declared scope, and exact note content before it can call a provider. It rejects undeclared or excessive note content and rechecks permissions after review. Model weights download only after approval; source text goes to a same-origin worker. Generated Markdown is displayed as text and applied only through an explicit, stale-source-checked edit. No protected API key is present in the static client bundle. Future hosted adapters must keep credentials in a trusted server environment and receive an explicit data-flow review. See [AI foundation](ai-foundation.md).

External Markdown, YAML, JSON, ZIPs, files, and dropped folder names are untrusted. Zod validates domain records and the ZIP manifest. Vault paths reject traversal and unsafe ZIP entry names; import limits file counts and declared sizes and checks note SHA-256 values. YAML alias expansion is disabled and frontmatter has a size cap. Markdown preview skips raw HTML and never executes note content. Imported files are user-selected; file type or extension alone is not a safety guarantee.

Archived revisions are validated and their Markdown checksums are checked before ZIP import or restore. History preview and diffs render source as text. Restore checks the current note revision and path reservation inside one IndexedDB transaction; a collision or stale edit fails without overwriting content. History stays in the local browser profile and is included in a vault ZIP, so those files can contain earlier text that was removed from the current note. See [version history](version-history.md).

Reading Mode renders math through KaTeX and diagrams through Mermaid with strict security. Mermaid SVG is displayed through a Blob image URL rather than injected into the DOM. Wiki references and embeds are interpreted as display data, and note source is never run as JavaScript. A dedicated review of URL schemes, generated SVG, and resource limits is still needed before treating arbitrary shared vaults as trusted.

Internal link annotations are parsed as UUID data and never evaluated. Rename previews list affected files; applying edits checks each source revision and writes within one IndexedDB transaction. Link and mention scans load local note bodies only while the inspector is open. Ignore choices are stored per vault and target note in localStorage and may be lost if browser storage is cleared.

Property values and schema definitions are validated before structured edits. The panel uses the YAML syntax tree to update selected keys and does not render YAML as HTML. Tag reference changes require a visible preview and recheck note revisions at commit time. The scanner avoids frontmatter comments and code regions, but Markdown syntax has edge cases; review the affected-file preview before a vault-wide tag change.

Attachments can be opened as browser Blob URLs. Exercise caution with untrusted downloaded files and links. URL protocol, archive decompression, and attachment preview behavior need a dedicated security review before broad public deployment. ZIP import currently uses library parsing and size guards but does not provide a sandbox against a malicious parser exploit.

The PDF reader processes local attachment Blobs through PDF.js's browser worker and renders pages as canvas plus a selectable text layer. It does not render PDF scripting or write annotations into PDF bytes. Annotation text is rendered by React as text. Stable link fragment IDs and annotation records are validated, and temporary PDF Blob URLs are revoked when the reader closes. Malformed or very large PDFs still warrant parser and memory stress testing before broader deployment.

OCR uses a same-origin browser worker, local WebAssembly, and packaged English, Swedish, and Arabic language files. The provider configuration contains no remote model or OCR endpoint. Images and scanned PDF pages stay in the browser, and source bytes remain unchanged. OCR text is rendered as text, validated before storage, and included in user-controlled ZIP exports. OCR can misread sensitive content; users review corrections before save. A future remote provider must require a clear opt-in and a separate data-flow review. See [OCR](ocr.md).

The browser transcription provider downloads speech model weights on first use, then runs recognition in a same-origin Web Worker. Source audio samples are sent only to that worker and are never uploaded to the model host. The worker and ONNX runtime are bundled with the application. Transcript segments are validated before storage and rendered as text; no transcript content is executed. The model download needs internet access initially and is separate from user media. See [transcription](transcription.md).

The app's error logger records action codes and boundary names without note bodies or attachment contents. No server secrets are exposed to the frontend. The generated service worker caches same-origin static assets, not private note content.

Full-text indexing and query evaluation stay in the browser. Search messages sent to the dedicated worker never leave the origin. Regular expressions are length-limited and reject a common nested-quantifier form; they run off the UI thread. The guard is not a complete proof against expensive patterns, so regex remains optional and needs broader adversarial testing before searches over untrusted shared vaults.

Semantic embeddings run in a same-origin worker. The user explicitly starts the local index; only pinned model and tokenizer files are fetched from Hugging Face. Note bodies and search queries are not sent to an embedding service. The vectors and source passages remain in origin-scoped IndexedDB, where they have the same local-device exposure as ordinary note storage. No remote embedding provider is configured. Future remote adapters must require the AI scope review before transmitting source text. The local model download and cache do not provide encryption or a backup.

Vault chat is also disabled by the AI policy until explicitly invoked and scoped. Retrieval bounds the material presented for review to four real Markdown passages, and `AiGateway` checks scope and permission again before invoking the local provider. Previous assistant answers are not silently carried into a later request with a different scope. Source references are constructed from retrieved note records; returned labels outside that set, or answer lines without citation labels, produce an insufficient-evidence response. This verifies citation identity, not the factual correctness of every generated claim. Saved chat history is optional, browser-local, unencrypted IndexedDB data; deletion and JSON download are available in the chat view.

Knowledge organization scans run locally and never write during discovery. Model requests use the existing explicit gateway review. Model suggestion JSON is validated, and evidence must be present verbatim in the reviewed content. The UI previews every accepted edit; safe batch edits use revision checks across the vault. Moving a note and creating an index require separate acceptance and are never included in the batch. See [knowledge organization](organization.md).

Shortcut overrides and recent note IDs are parsed and validated from localStorage. Commands are trusted application or future plugin code; note content is never evaluated as a command. A future plugin runtime must define permissions and review rules before allowing third-party command handlers.

Bookmark records validate kind-specific targets, group ancestry, and HTTP(S)-only external URLs before writing. External bookmarks open with `noopener,noreferrer`; their titles are rendered as text. Heading and block bookmarks read Markdown as data. Vault ZIP import remaps internal IDs and rejects cyclic bookmark groups. Recent notes and searches are browser-local preferences rather than network telemetry.

The graph reads Markdown and attachment metadata locally. Link text becomes canvas labels through Sigma and is never interpreted as HTML. Layout and link parsing run in a same-origin Web Worker. Attachment nodes download through short-lived Blob URLs; no attachment binary enters the graph worker.

Bases validate saved configurations with Zod before loading or writing. Query expressions run in the local search worker. Note property edits use typed YAML input parsing and the repository's revisioned save path. Map coordinates are parsed as data and shown on a local coordinate grid; no geocoding service receives location text. Card images load from local attachment Blob URLs and are revoked after use.

Canvas documents and imported JSON Canvas files are Zod validated with limits on card counts, connector counts, text lengths, geometry, and URL schemes. Text cards render Markdown without raw HTML. Website cards accept only HTTP(S) URLs and open with `noopener noreferrer`; Canvas does not run JavaScript from card contents. Note and attachment cards read existing vault data lazily. Media previews use temporary Blob URLs, which are revoked when cards unmount. Large Canvas documents still need performance and accessibility review before use with untrusted shared vaults.

Base formulas use a dedicated parser and interpreter, not `eval` or JavaScript function construction. The grammar has no member access, indexing, assignment, or arbitrary calls; functions come from a fixed allowlist. Only primitive property values enter expressions; missing or structured values become null. Source length, token count, nesting, function arguments, evaluation steps, and string size are bounded. Formula definitions are compiled during Base validation, including ZIP import. Computed values remain in browser memory and are not sent to a server. See [formula syntax](formulas.md).

Template expressions use a separate bounded parser with an allowlist of string, date, property, and conditional functions. No arbitrary JavaScript, member access, file access, or network calls are available. Source, expression count, expression nesting, frontmatter, and rendered output sizes are limited. Applying YAML properties parses both documents with alias expansion disabled and preserves existing target values. Clipboard text enters a template only after the user presses Read clipboard and the browser grants access. See [templates](templates.md).

Periodic note filename and display patterns use a fixed token formatter. Filename validation rejects unsafe characters and tested collisions across adjacent periods and years. ZIP import validates period formats before applying settings. Period identity fields are Markdown YAML data and do not execute code. Auto-create runs only for the period the user opens or selects, and never generates a range of notes. See [periodic notes](periodic-notes.md).

Task metadata uses fixed, bounded inline tokens; custom recurrence intervals have a validated upper bound. Saved task filters compile to local predicates without `eval`, regular expressions supplied by a note, or network calls. ZIP import validates saved task queries. Dashboard edits verify the latest source task before saving. Assignee names are text metadata, not authenticated shared-vault identities. See [tasks](tasks.md).

Calendar event forms validate title, dates, times, and body length before writing portable Markdown. Drag payloads contain only an item ID and are matched against visible local summaries. Date moves reload the source note and reject stale property dates before a revisioned save. See [calendar](calendar.md).

Before broader cloud rollout, verify owner isolation, immutable encryption mode, encrypted attachment storage, and recovery across devices against a live Supabase project. Obtain an independent cryptographic review and define deletion/retention of old ciphertext and blobs. The [encryption threat model](encryption.md) describes key loss, visible metadata, and current rotation limits. See [sync protocol](sync-protocol.md).
