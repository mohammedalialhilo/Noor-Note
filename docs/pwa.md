# Installable offline app

Noor Note ships a web app manifest, square 192 and 512 pixel PNG icons, an SVG icon, and a maskable 512 pixel manifest entry. The SVG is the vector source for the install icon family; PNG copies provide broad browser support. The manifest starts at `/` in a standalone window. The static Next.js export is deployed over HTTPS on Netlify.

After the first successful production visit, the service worker caches the public app shell, Next.js static chunks, and local worker scripts. Notes, folders, and attachments remain in IndexedDB and OPFS; the worker does not store vault content. The shell can open without network access, and local vault actions continue through the repository. The status bar and Settings show network and offline-shell state. A browser install prompt is offered only when the browser supplies one; other browsers can use their own Install app or Add to Home Screen menu.

OCR and transcription runtime files are on an explicit static allowlist but cache only when requested. This keeps the first install smaller. A specific language or runtime is available offline only after it has been used online. Remote AI model files have their own browser cache and are not part of the PWA shell.

Updates install in the background and wait. The workspace displays **Update now** when a new worker is ready. Clicking it flushes pending note edits before activating the waiting worker; the tab reloads after the controller changes. The worker checks for updates when the browser comes online, when the tab becomes visible, and hourly while visible. Netlify serves `sw.js` with `no-store` headers so update checks reach the current worker script.

The generated worker intercepts only emitted public static asset paths and three known app-shell navigation routes. It never caches navigation responses, authenticated requests, private share or published pages, API routes, Netlify Functions, cross-origin responses, or a response marked `private` or `no-store`. Static asset fetches omit credentials. Sign-out removes account-scoped Cache Storage names if present and keeps the public shell and local vault databases; the Supabase SDK clears its own session. Browser storage remains subject to user clearing and eviction, so export vault backups regularly.

`scripts/generate-service-worker.mjs` hashes allowed emitted files and fills `scripts/service-worker-template.js` after the production build. Do not edit generated `out/sw.js`. `usePwa.ts` owns registration and install/update UI state. `pwa-cache.ts` owns sign-out cache cleanup. The worker and manifest have artifact tests, and the browser prompt has a component test. A deployed browser install/offline/update test remains necessary before claiming cross-browser coverage.
