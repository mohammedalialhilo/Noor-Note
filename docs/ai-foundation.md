# Optional AI foundation

AI is disabled by default. Notes, search, editing, OCR, and transcription remain usable without AI note actions. OCR and transcription are separate user-invoked local tools. Settings store the AI policy in this browser, outside vault ZIPs.

The policy has two modes: **disabled** and **only when explicitly invoked**. Enabling the latter does not grant note access. Current note, selected notes, Base results, and vault retrieval each require a separate scope permission. Turning AI off clears every scope permission. Malformed or unavailable preference storage falls back to disabled. Vault retrieval is designed to pass only the reviewed matching notes, never an unseen full-vault dump.

`packages/ai` owns provider-neutral contracts for chat completions, embeddings, transcription, OCR, and future image understanding. A public provider descriptor states its name, model, execution location, capabilities, and the recipient HTTPS origin for an external provider. Descriptors contain no credential or endpoint query string. The browser OCR, transcription, and note-action providers expose on-device descriptors. No external provider or embedding provider is connected.

`AiGateway` creates a bounded request plan with the provider descriptor, exact scope, user prompt, and exact Markdown supplied from each included note. An action can supply only a selected excerpt; the review displays that excerpt. The gateway rejects content outside the declared IDs or vault, duplicate IDs, excessive context, disabled mode, or a missing provider. The caller presents a copy of this full plan and receives a fresh approval for each invocation. The gateway rechecks the provider and permissions before dispatch. A declined, canceled, or invalid request never calls the provider. Chat output and embedding vectors receive runtime validation.

Note actions run through a pinned SmolLM2 135M Instruct ONNX model in a same-origin worker. The first explicit generation downloads approximately 182 MB of model weights from Hugging Face. Only model files are fetched; note content is posted to the local worker after request review. The browser cache may retain downloaded model files. The small model works best with short English text; actions reject input over 2,500 characters instead of silently truncating. Translation, contradiction detection, and structured extraction can be unreliable; every result remains a suggestion.

The command palette registers all 19 note actions. The note menu opens the same action dialog. Each request shows the exact instruction and source text before generation. A result stays in an editable preview with a planned Markdown change. Accept, Insert below, Replace selection, Reject, and Undo are explicit controls where applicable. Applying checks the current note against the reviewed source and uses CodeMirror history for Markdown undo. Suggested titles use the normal note save path and an explicit title undo control. Suggestions are not persisted until accepted; no action silently overwrites a note.

Vault chat provides reviewed, retrieval-based questions over selected sources with real note citations; it is separate from note actions. There is no automated background AI job, server endpoint, or credential form. Semantic search has its own explicitly enabled local embedding index; it does not grant AI note actions or vault chat permission to retrieve notes. A future hosted adapter must keep protected API keys in a trusted server environment and pass through the same review gate. Do not put provider secrets in `NEXT_PUBLIC_` variables, localStorage, the service worker, or the static bundle. The local model has unit and UI flow tests; a real-browser first-download and generation test remains outstanding. See [vault chat](vault-chat.md).
