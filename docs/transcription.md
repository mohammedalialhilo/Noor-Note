# Audio and video transcription

Open an audio or video attachment in the file explorer, use its **Transcribe media** context action, or use **Open transcription** to upload a file. Saved voice recordings are ordinary audio attachments and can be opened the same way. Noor Note saves the original media first. Run transcription, review and edit timestamped segments and optional speaker labels, then save the transcript. Clicking a timestamp seeks playback. Select segments to create a note, task note, quote, or copy a timestamp link.

`TranscriptionProvider` separates recognition from the panel and storage. The initial `BrowserWhisperProvider` decodes supported audio through the browser and runs a multilingual Whisper tiny model in a dedicated Web Worker. The first run downloads model files from Hugging Face into the browser cache; subsequent runs can reuse that cache offline. Media samples stay on the device. The ONNX WebAssembly runtime and worker are bundled in Noor Note's static build and precached for offline use. No hosted transcription provider is configured. Future local model packs or explicitly selected hosted providers can implement the same interface without changing transcript storage.

`Transcript` is a validated sidecar tied to the source attachment UUID. It has a stable ID, provider and optional language, combined corrected text, timestamps, and segments. Each segment has a stable ID, start and end time in milliseconds, editable text, nullable speaker, and nullable confidence. The current provider does not supply diarization or calibrated confidence, so these fields remain null until provided or edited. Original audio and video bytes are never changed. Trash and restore retain transcripts; permanent deletion removes them. Vault and folder ZIPs include transcript JSON and remap IDs on import.

Offline search indexes each saved segment separately, so a search hit opens the original media at that segment's time. Search indexes corrected segment text and speaker labels, not temporary recognition drafts. `has:transcript` finds transcript segments. New notes, tasks, and quotes use a portable relative media link with a time fragment. The separate **Copy time link** action creates a Noor Note app URL with an attachment ID and millisecond timestamp; it opens the panel and seeks playback. Pasted app URLs can require adjustment after moving a vault to another deployment.

Current limits: the initial model requires a network download on first use and may be large. Decoding currently accepts browser-supported audio formats up to 250 MiB and 30 minutes. Some video containers cannot be decoded directly by the browser audio API; the panel still plays those files, but transcription reports the unsupported track. No speaker identification is performed. The worker reports model download progress but not fine-grained inference progress. Model accuracy, speed, and available memory vary by device; long recordings need broader browser testing. Transcripts share the 50 MB ZIP manifest limit with other structured records. There is no browser end-to-end speech model test yet.
