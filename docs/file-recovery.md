# File recovery

Open **Recovery Center** from the activity bar, workspace navigation, or command palette. The center is scoped to the active vault and reads four existing sources:

- **Deleted notes and attachments:** The local Trash retains content and bytes until permanent deletion. Restore uses the original path and can fail if that path is occupied; Restore as copy creates a separate item with a collision-safe name. Deleted folders remain managed in Trash.
- **Recent revisions:** The 50 most recent local checkpoints come from an indexed vault-and-time query. A revision can be previewed, restored to an active note, or copied to a new note. The current checkpoint cannot be permanently deleted. Restoring a revision creates another checkpoint, preserving the previous content.
- **Unsaved recovery snapshots:** Noor Note keeps at most one browser-local draft per note when autosave is pending or fails. Recovery Center lists validated drafts whose text differs from the stored note, including orphan drafts. Restoring a draft to its note requires confirmation and an unchanged saved revision; Restore as copy leaves the original untouched. Deleting a draft removes that browser-local snapshot. These drafts are not cloud backups and are lost if site data is cleared.
- **Sync conflict copies:** Existing sync behavior preserves divergent notes and attachments as separate active copies with Noor Note conflict suffixes. Recovery Center identifies those copies by their naming pattern; renaming a reviewed copy removes it from this list. There is no durable conflict registry yet, so a user-renamed conflict copy is not detectable as a conflict. The center never automatically merges or deletes conflict content.

Previews render Markdown as inert text. Recognized image files receive a signature check before an image preview; other attachments show metadata without rendering untrusted bytes. Actions that permanently delete content require confirmation. In a shared vault, server authorization for cloud changes remains separate from the browser UI. Recovery Center is local-first; it does not retrieve content already purged from browser storage or reconstruct older drafts that were never saved.
