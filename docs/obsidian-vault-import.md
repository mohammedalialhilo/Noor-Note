# Obsidian-style Markdown vault import

Select a ZIP archive containing a Markdown vault, select a browser-supported folder, or drop a folder into the file explorer. The Import Center previews folders, Markdown notes, attachments, JSON Canvas files, path conflicts, and a reference report before writing. It preserves Markdown source, including wiki links, aliases, body tags, YAML properties, relative links, callouts, and image embeds. Noor Note reads metadata from the source without rewriting the file.

Compatible `.canvas` files are imported as Noor Canvases using the existing JSON Canvas parser. Note and attachment cards are connected to their imported vault objects after those files are saved. Unsupported Canvas `subpath` and group background fields are reported. An incompatible `.canvas` file remains an attachment so the original bytes can be exported later. Explicit empty directory entries in ZIP archives become vault folders; browser folder selection may omit empty directories because the file picker supplies files rather than a directory listing.

The report has four sections: successful folder/file actions, warnings, unsupported syntax, and unresolved references. It is shown in preview and can be downloaded as JSON after import. Reference checks cover wiki links and embeds, aliases, headings, blocks, relative Markdown links, Markdown image links, attachments, and Canvas file cards. Checks use the selected source files; a reported missing target may already exist in the destination vault. Dataview, Tasks, Excalidraw, and query plugin code blocks remain verbatim source and are reported as unsupported syntax. The importer never runs their code.

The existing Import Center conflict rules apply. Renaming an imported path to avoid a collision can change where source links point; the report warns about this and leaves Markdown intact for manual review. Canvas file cards are remapped to the final imported note or attachment path. Skipped or conflicting destination content is not used to silently rewrite source links. Loose imports remain sequential and may leave earlier items in place after a later storage error.

`apps/web/src/lib/obsidian-vault.ts` owns source-vault reference analysis and JSON Canvas validation. `import-center.ts` coordinates inspection, conflict planning, and repository writes. `apps/web/test/obsidian-vault.test.ts` exercises nested and empty folders, YAML aliases/properties, tags, wiki and relative links, images, Canvas references, unsupported plugin syntax, and missing targets. JSON Canvas behavior follows the [JSON Canvas 1.0 specification](https://jsoncanvas.org/spec/1.0/); only fields represented in Noor Canvas are imported.
